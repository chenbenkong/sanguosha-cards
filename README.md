## 一、这是什么

这是一份个人整理的三国杀武将资料库，最初只是想把手上的卡牌图片做成能翻、能查的网页，后来逐步补上了武将档案、技能说明、传记，以及最花功夫的部分——**逐条对齐的真人语音台词**。

它不是游戏，也不是模拟器，而是一个「可以拿起来转一转、翻过来看背面、点开听原声」的收藏展示站。所有内容都经过整理与校订，尤其台词部分不以维基文本为准，而是以**实际播放的那段音频**为准。

### 适合谁看

- 想快速查某个武将的技能、称号、势力、台词与传记
- 想听某个武将的官方配音，并看到与音频逐字对应的台词
- 想看卡牌正反面设计、收集不同皮肤的卡面
- 想参考一套「纯静态 + WebGL + 语音同步」的前端实现

## 二、主要功能

### 1. 卡墙与检索

- **704 位武将**按势力（魏 / 蜀 / 吴 / 群 / 神等）分组展示，主公卡有独立标识。
- 支持按**武将名、称号、技能名、画师、卡包、势力**做关键词搜索与多条件筛选。
- 双主题（浅色 / 深色）一键切换，配色与卡面描边同步适配。
- 响应式网格：手机端自动变两列，不出现横向滚动。
- 灯箱大图：点开可放大查看，支持 `←` / `→` 翻页、`Esc` 关闭、下载原图（WebP）。

### 2. 3D 卡牌交互

- 首页卡片**按住拖动即可自由旋转**，鼠标悬停不会自己动（避免误触）。
- 支持**翻转到背面**，背面文字按正常阅读方向排版，不做镜像。
- 卡面字体统一：姓名使用专门的字体子集，生僻字（如「彧」、SP 系列用字、偏僻字）不会出现「一个名字两种字体」的拼接感。
- 实现要点：全站复用**同一个 WebGL 上下文**，卡片进出格子时把渲染目标在挂载点之间搬家，而不是给每张卡各建一个画布；`rotY` 无限累加不设限位，松手后平滑归位。

### 3. 武将详情面板

点开卡片后可查看（面板已加宽，尽量不用下拖）：

- **技能**：技能名与效果说明
- **台词 · 原声**：按技能分组的逐句台词，每句前带播放按钮
- **传记**：武将生平文字
- **基础信息**：势力、体力、称号、卡包、画师、品质等

### 4. 原声语音与逐句卡拉 OK

这是本项目最核心、也最费工的部分。

- 全站 **3036 条语音**，覆盖 **704 / 704 位武将**，无缺漏。
- 播放时文字会随音频进度做**逐字高亮**（底层文字 + 覆盖层按 `--pw` 进度裁切），像卡拉 OK 一样。
- **全部为官方真人配音，已移除合成朗读**，不会用系统 TTS 冒充角色原声。
- 找不到本皮肤语音的武将，会借用同角色其他皮肤或同性别、同势力相近角色的官方原声；借用时**台词文字跟着音频一起换**，所以听到什么就看到什么。
- 语音文件取自官方 CDN，按 `<folder>/<File>.mp3` 索引；前端只做播放与进度同步，不做音频加工。

## 四、语音台词是怎么对齐的

这一节解释为什么本站的台词和「随便抄一份维基台词」不一样。

**踩过的坑**：官方参考资料里的音频地址是按拼音推测皮肤音频拼出来的，同一个 `<folder>/<File>.mp3` 常常被挂上多个皮肤的多套文本（全库约 342 处冲突）。例如曹操「奸雄」那条音频，资料里同时存在「夫英雄者，在志高…」和「大忠似奸，留一世功名…」两种写法，而实际音频念的是「挟天子以令不臣。」——照着资料改只会越改越乱。早期还试过把十几张卡的语音拼成一条长音频做批量识别，时间轴漂移导致整组台词错位（例如把「就是穿肠的药」写到阵亡语音上）。

**最终做法**：只认音频本身。

1. 从官方 CDN 下载原声，用 ffmpeg 解码为 16 kHz 单声道 PCM。
2. 把每条语音放进**固定长度的时隙**（10～11 秒，不足补静音），拼成无损 WAV。时隙起点是精确已知的，因此不再需要任何时间轴拟合，从根上消除漂移。
3. 对每个 WAV 做一次语音识别，得到带时间戳的分句；按 `floor(时间戳 / 时隙长度)` 归位，边界提前量做进位修正，同一时隙内的多句合并成一条台词。
4. 结果写入 `voice_text_authority.json`，键是小写化的 `folder/File.mp3`——**以音频文件为单位**，而不是以武将为单位。
5. 构建时最后一步统一覆盖：无论哪张卡引用了这段音频（包括借用卡），显示的文字都换成该音频的实际听写结果。这份权威表随仓库源码保存，重新构建不会回退。
6. 官方录入文本只用于**规范同音字**（相似度阈值 ≥ 0.72 才替换），例如「伯父 → 伯符」「唯 → 维」「灵溪 → 灵犀」「良配 / 紫莲 → 梁沛 / 子廉」，从不用来推断整句。

因此全站 3036 条语音里，790 处是逐条听过写下来的，其余 2246 条与官方逐条录入文本一致，**没有「未核对且存疑」的条目**。

## 五、技术架构

- **形态**：单页静态站。`index.html` 内联全部 CSS、JS 与 704 条卡牌数据；档案数据按需从 `data/*.json` 异步加载（只取一次）。
- **3D**：Three.js 打包进 `vendor/card3d.js`；卡背用 `CanvasTexture` 绘制并关闭 UV 镜像；拖拽用 `window` 捕获 `pointermove`，松手后 `settle()` 平滑归位；CSS 层禁用 `translate` 位移以保证悬停稳定。
- **语音**：`Audio` 逐句播放 + 时间进度驱动文字高亮；音频地址前缀为官方 CDN；播放按钮与文案明确标注为原声。
- **字体**：姓名用思源宋体子集 `fonts/names.woff2`；制卡阶段对生僻字使用逐字字体并做简繁转换，避免字体回退造成的拼接感。
- **图片**：官方大图经裁切、合成、署名清理后，以 `sharp` 重压为 q92 WebP；每张卡在构建时用「插画区近黑像素占比」自动检查是否有漏画（阈值 0.60），当前全站 733 张卡图空白数为 0。
- **缓存**：静态资源带 `?v=62` 版本号，更新后浏览器会拉新数据。
- **隐私**：不加载第三方统计脚本、不写 Cookie（仅主题偏好等本地设置用 `localStorage`）、不收集任何用户数据。

## 七、本地运行

不需要安装任何依赖，用任意静态服务器即可：

```bash
cd sanguosha-cards
python -m http.server 8090
# 打开 http://127.0.0.1:8090
```

也可以用 Node：`npx serve .`。

> 直接双击 `index.html`（`file://`）能看卡墙，但浏览器会限制 `fetch` 读取 `data/*.json`；要听语音、看传记，请务必用本地服务器打开。语音音频本身来自官方 CDN，需要联网。

## 八、重新生成与构建（源码工程）

源码工程中的主要脚本与职责：

| 脚本 | 作用 |
| --- | --- |
| `tools/build_page.mjs` | 总构建入口：生成档案 → 语音总装 → 内联打包 → 卡图空白检查 → 写出 `out/web/index.html` |
| `tools/make_lore.mjs` | 从页面内嵌 `DATA` 生成 `lore.json` / `story.json` / `voice.json` 基线 |
| `tools/make_voice.mjs` | 合并基线、逐条听写补录、同性别借用、人工复核，最后应用 `voice_text_authority.json` 按音频覆盖台词 |
| `voice_text_authority.json` | **权威台词表**：705 段音频 → 实际听写文本，构建链的最后一道覆盖 |
| `tools/check_blank.py` | 检查卡图插画区是否有纯黑漏画 |
| `tools/repress_cards.mjs` | 卡面重压为 WebP |
| `tools/make_namefont.mjs` | 生成姓名用字体子集 |
| `tools/card3d-src.js` / `card3d-client.js` / `card3d.css` | 3D 卡牌内核与封装 |
| `tools/detail.js` / `detail.css` | 详情面板与语音播放逻辑 |
| `tools/_v60*.mjs` / `_v60*.py` | 语音听写流水线（诊断 → 固定时隙拼接 → 识别结果归位） |

标准重建命令：

```bash
node tools/build_page.mjs
```

构建日志会依次打印档案条数、语音总装统计（原有 / 新增真原声 / 借用 / 仍缺）、卡名字体字数、以及「插画区黑占比 > 0.60」的卡图数量（应为 0）。之后把 `out/web` 的内容同步到本仓库 `main` 分支即可，GitHub Pages 会自动更新。

## 九、部署

### GitHub Pages（当前仓库）

1. 仓库设置中 Pages 来源设为 **`main` 分支 / 根目录**（root）。
2. 根目录的 `.nojekyll` 保证下划线开头文件与中文文件名原样发布。
3. 发布地址：`https://chenbenkong.github.io/sanguosha-cards/`。
4. 首次启用需要等待 1～3 分钟构建；之后每次推送到 `main` 会自动重新发布。

### 其他静态托管

因为全部是相对路径、没有服务端逻辑，任何静态托管都能直接放：腾讯云 COS / 阿里云 OSS / Cloudflare Pages / Netlify / Vercel 均可，把仓库根目录当作网站根目录上传即可。若平台限制产物体积（常见 50 MiB），需先压缩卡图；本仓库保留的是画质优先的 214 MiB 版本。

### 站点镜像

WorkBuddy 托管版本与 GitHub Pages 内容一致，主要用于国内访问；更新时两边同步推送。

## 十一、已知限制

- **语音需要联网**：音频直连官方 CDN，断网时卡面与档案仍可浏览，但无法播放原声。
- **仓库体积较大**：约 214 MiB，首次 `git clone` 或 Pages 首次构建会慢一些。
- **中文文件名**：请不要重命名 `cards/` 下的文件，`index.html` 里保存的是编码后的路径，改名会造成 404。
- **WebGL 依赖**：3D 卡面需要浏览器支持 WebGL；极旧浏览器会降级为静态卡面。
- **`_headers` 在 GitHub Pages 上不生效**：它只给原托管平台用，Pages 的缓存策略由 GitHub 统一管理。
- **卡面水印**：水印已烧进图片像素，无法用 CSS 去除。
